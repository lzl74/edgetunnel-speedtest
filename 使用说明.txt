CF 优选测速器 cfspeed v1.2
================================

测 Cloudflare Worker / edgetunnel 的优选 IP、优选域名,在你当前网络下的真实质量。
可以拷到任何一台 Windows 电脑上跑,测的是那台机器所在网络的情况。


零、v1.2 改了什么
-----------------
1. 同一个域名不再重复出现
   一个域名常有 2 条 A 记录,以前会变成两行同名结果。现在合并成一行,
   取表现最好的那个 IP,其余 IP 记在下方"备选"里。
   想回到旧行为(每个 IP 一行):加 --all-ips

2. 本地 DNS 污染不再误判
   运营商 DNS 有时会把域名解析到乱七八糟的境外 IP,导致误报"非 Cloudflare IP"。
   现在本地解析拿不到 CF IP 时,会自动用 DoH(1.1.1.1)复核一遍。
   实测 426 个域名里有 8 个是这么救回来的。
   关掉这个行为:加 --no-doh

3. 网段判断更准
   以前只认官网 ips-v4 的 15 个段,会把 104.28.x、1.1.1.1 这类真 CF 地址误判成非 CF。
   现在用 cf_ranges 的权威库(官网清单 ∪ AS13335 宣告),共 475 块 / 约 190 万地址。

4. 淘汰原因说得更清楚
   区分"DNS 解析失败"、"不在 CF 段"、"确实迁出"三种情况。


一、内置预设(最省事)
--------------------
双击 exe → 输入方式选 [1] 使用内置预设,再选测什么:

    [1] 全部域名    426 个优选域名
    [2] 全部 IP      1277 个唯一 IP(实测东京 54 + 网段 5×254 + 节点 7,已去重)

选了"全部 IP"会提示目标偏多,采样轮数建议给 1~2,否则耗时较长。

命令行也能用,粒度更细(--preset):
    --preset domains    优选域名 426 个(你之前给的全量列表)
    --preset tokyo      东京网段 5 个 /24,扫完约 20 秒
    --preset ips        已实测可用的东京 IP 54 个
    --preset nodes      原始订阅节点 11 个(保留各自的 2053/2083/8443/2096 端口)

例:
    cfspeed.exe --preset ips -w 你的域名 -r 5
    cfspeed.exe --preset nodes -w 你的域名 -r 3 -s

注意:预设只是"候选清单",具体哪个好还是要在你当前网络下实测。
换个网络,结论会变。

预设里的 IP 已逐条核对过,全部落在 Cloudflare 地址空间内:
    TOKYO_IPS 54/54、TOKYO_NETS 5×254 全部、NODES 里的 7 个字面 IP 全部。


二、为什么不用 ping
------------------
TCP 握手快 ≠ 好用。有些 IP 握手只要 50ms,但 TLS 要 500ms,带宽只有 2Mbps。
本工具测四件事:
    TLS 握手  →  HTTP 首字节  →  实际下载带宽  →  落点机房(CF-RAY)
并且默认多轮采样取中位数,避免"测一次就下结论"的误差(单次误差可达 ±200ms)。


三、怎么跑
----------
方式 A:双击 cfspeed.exe,按提示输入(推荐)
    第一步会让你填 Worker 域名 —— 程序里不内置任何域名,必须自己输入。
    交互模式下不会一上来就问"要不要测带宽",而是先把连通性和首字节测完,
    告诉你"可用 N 个",再问要不要测下载带宽、测前几名 —— 这样你心里有数,
    不至于对着一堆根本连不上的目标浪费时间。

    全部测完后不会直接退出,而是问你要导出前几名:
        可用 2 个。要导出前几名?(直接回车结束)
        前几名: 3
        前 3 名(ip:端口#机房):
           1  162.159.152.2:443#SJC
           2  172.67.75.172:443#AMS
        已保存: top3_20261102_142151.txt
    可以反复输入不同数字导出不同份数,直接回车才退出(窗口会等你按回车,
    不会一闪而过)。
方式 B:命令行
    cfspeed.exe --preset ips -w 你的域名
    cfspeed.exe -t 1.2.3.4,example.com -w 你的域名
    cfspeed.exe -f list.txt -r 8 -s
    cfspeed.exe -c 162.159.38.0/24 -w 你的域名

参数:
    -t  目标,逗号或空格分隔,IP 和域名都行,可带端口(1.2.3.4:2096)
    -f  从文件读(每行一个)
    -c  扫描网段,如 162.159.38.0/24
    --preset  使用内置预设
    -w  Worker 域名 —— SNI 和 Host 都用它,必须填你自己的(命令行不填会直接报错)
    -r  采样轮数,默认 5,建议 5~10
    -s  额外测下载带宽(慢,建议先筛出候选再测)
    -p  端口,如 443,2096(默认只测 443;目标自带端口时以自带的为准)
    -n  并发数,默认 60
    --all-ips   同一域名的多个 IP 各占一行(默认合并成一行)
    --no-doh    关闭 DoH 兜底解析(默认开启,用于绕过本地 DNS 污染)
    --max-ips   每个目标最多测几个 IP,默认 2


四、最重要的一个参数:-w
----------------------
-w 必须填你自己的 Worker 域名,不是优选 IP 的域名。
原理:优选 IP 只是"进 Cloudflare 的门",TLS 握手的 SNI 和 HTTP 的 Host
必须是你自己的 Worker 域名,否则证书对不上,连不上。

比如你的 Worker 是 abc.workers.dev,就用 -w abc.workers.dev。
填错了所有结果都会显示"证书不匹配"。


五、结果怎么看
--------------
  机房   Cloudflare 落点。NRT=东京 SIN=新加坡 LAX=洛杉矶 AMS=阿姆斯特丹
         HKG=香港 LHR=伦敦 SJC=圣何塞
  中位   多轮采样的中位数,主要看这个
  最快   所有采样里最快的一次,代表这条线路的物理下限
  抖动   标准差,越小越稳
  带宽   Mbps,注意测速是串行做的,并发测会互相抢带宽导致数值偏低

判断标准(经验值,不同线路会有差异):
   中位 < 300ms  且  带宽 > 30Mbps   →  好用
   中位 300~600ms 且 带宽 > 30Mbps   →  能用
   带宽 < 10Mbps                     →  基本不能用,别选


六、注意事项
------------
1. 单次结果不可信。同一个 IP 连测三次,中位数能差 100ms 以上。建议 -r 至少 5。
2. 前几名的差距常在噪声范围内。别追求"最优",挑 2~3 个轮换更实际。
3. "哪个网段落哪个机房"取决于你的运营商路由,换网络就变了,必须重测。
4. 不同时段差异可能比不同 IP 的差异大得多(晚高峰会明显变慢)。
5. 结果会自动存成 cfspeed_日期_时间.csv,在程序同目录。

只有 200 且有 CF-RAY 响应头的才算可用。没有 CF-RAY 的会返回 403,
这类 IP 看着能连上,实际不服务你的域名。


七、网段库与清单清洗(cf_ranges.py)
-----------------------------------
cf_ranges.py 是配套工具,负责回答"这个 IP 到底是不是 Cloudflare 的"。

判断依据不是官网那 15 个段,而是:
    官网 ips-v4 / ips-v6  ∪  AS13335 宣告的全部网段
合并后共 475 块 IPv4 / 约 189 万个地址,缓存在 cf_ranges.json。

常用命令:
    python cf_ranges.py --update              联网刷新网段库(建议每月一次)
    python cf_ranges.py --info                看当前库的规模和更新时间
    python cf_ranges.py --check 104.28.1.1    查某个 IP / 网段属不属于 CF
    python cf_ranges.py --clean cidrs.txt     清洗网段清单(自动备份 .bak)
    python cf_ranges.py --clean cidrs.txt --dry   只统计不写入

--clean 会做四件事:
    1. 剔除非 CF 段(垃圾 VPS 网段,扫了纯浪费)
    2. 裁剪只部分重叠的段,只保留其中属于 CF 的部分
    3. 补齐缺失的 CF 段(保证不漏掉可用 IP)
    4. 去掉被其他条目包含的冗余子集

本目录的 cidrs.txt 已经清洗过一次,结果:
    原始 1414 条 → 清洗后 1396 条
    剔除 335 条非 CF 段、裁剪 5 条、补齐 377 条、合并 60 条冗余
    覆盖率 100%(CF 全部 1,888,768 个地址都在清单里),零重叠
    原文件已备份为 cidrs.txt.bak

ip_scan.py 在扫描前也会自动校验网段(不需要手动跑 --clean),
不想校验就加 --no-verify。
